# Marathon Training Companion: Project Plan

Goal: improve the marathon training app in the weeks before the 2026 NYC Marathon (Nov 1). Make its training insights more accurate, prepare for race day, and keep it secure.

## Phase 1: Training insight features (Sept 30)
- **Predicted finish time:** make the adjustments for endurance and weekly mileage gradual, so one long run changes the prediction sensibly.
- **Past weeks:** add a list of past weeks, each with a status (done, short, missed).
- **Race Day pacing:** pace the NYC course mile by mile, effort-adjusted for its bridges and hills, with 5K and half-marathon checkpoints and a goal-time slider.
- **Pace Analysis:** build one combined weekly chart of miles and pace (longest run shown inside each weekly bar), and remove duplicate sections.
- **Best efforts:** explain why a mile split can differ from the "fastest mile" record (watch pauses, range labels).
- **Practice database:** set up a separate copy of the data so testing never touches the real records, plus scripts to back up and restore.
- **AI coach:** add a backup model and a friendly "busy" message when Gemini is overloaded.

## Phase 2: Design exploration (Oct 1–5)
- Try a redesign inspired by a MoMA poster: cobalt blue, cream and leaf green, heavy type, flat block buttons. Build it on its own branch with a backup tag.
- Review it with the owner and decide whether to keep it or the original design. Either way, keep the experiment on the `poster-redesign` branch.

## Phase 3: Race preparation and polish (Oct 6)
- **Fueling notes** (Race Day tab), written into the app rather than generated by AI, because Gemini's free tier is unreliable:
  - Everyday training meals, before a long run, after a long run, and when to stop alcohol (by the Wednesday before the race).
  - Race weekend: the day before, race morning, and a gel schedule by mile and clock time based on the goal pace.
- **Pace Analysis:** give both weekly charts the same clean date labels (every week, or one label per month), and line the pace points up with their bars.
- **Legend:** explain what the effort colours, run lengths and warning flags mean.

## Phase 4: Security (Oct 6)
- Update the framework (TanStack Start) to the version that fixes its known security flaw. Vercel blocks deploys until this is done.
- Run a full security review.
- Add hardening without changing who can get in or how the app works:
  - The server only accepts plain column names in database requests.
  - The Strava connection steps check their inputs.
  - The temporary Strava sign-in cookie is stricter.
